1. บทนำ

ส่วนขยาย Chrome "RSC Doc → Smart Data" พัฒนาโดยสถาบันพัฒนาและฝึกอบรมโรงงานต้นแบบ (สรบ.) มหาวิทยาลัยเทคโนโลยีพระจอมเกล้าธนบุรี เพื่อช่วยบุคลากรในหน่วยงานสกัดข้อมูลจากเอกสารราชการ (.docx / .pdf / .xlsx) แล้วกรอกข้อมูลลงแบบฟอร์มเว็บราชการ https://rsc-approval.kmutt.ac.th/ โดยอัตโนมัติ นโยบายนี้เปิดเผยโดยละเอียดถึงการเก็บรวบรวม การใช้ การจัดการ การจัดเก็บ และการแชร์ ข้อมูลทั้งหมดของผู้ใช้ ตลอดจนทุกฝ่ายที่ได้รับข้อมูล ตามนโยบายความเป็นส่วนตัวของ Chrome Web Store

2. ข้อมูลที่ส่วนขยายเก็บรวบรวม (Data We Collect)

ส่วนขยายเก็บรวบรวมข้อมูลเฉพาะที่จำเป็นต่อการทำงานหลัก (การสกัดเอกสารและการกรอกแบบฟอร์ม) ดังนี้:

2.1 ไฟล์เอกสารที่ผู้ใช้เลือก (Files & Docs)

  • ไฟล์ .docx / .pdf / .xlsx ที่ผู้ใช้ลาก/เลือกเข้าในส่วนขยาย — รวมถึงเนื้อหาทั้งหมดของเอกสาร (ข้อความ, ตาราง, ข้อมูลตัวเลข)
  • ชื่อไฟล์และขนาดไฟล์

2.2 ข้อมูลส่วนบุคคลที่ปรากฏในเอกสาร (Personal Information)

  • ข้อมูลที่สกัดได้จากเอกสาร เช่น ชื่อ-นามสกุล, ตำแหน่ง, หน่วยงาน, หมายเลขโทรศัพท์ติดต่อ, วันที่ ฯลฯ
  • ข้อมูลเหล่านี้มาจากเอกสารที่ผู้ใช้เลือกเอง — ส่วนขยายไม่ได้รวบรวมจากแหล่งอื่น

2.3 ข้อมูลการเงิน/งบประมาณที่อยู่ในเอกสาร (Financial Information)

  • วงเงิน, ค่าใช้จ่าย, รายการงบประมาณ/บิล ที่ปรากฏในเอกสารที่ผู้ใช้เลือก

2.4 การตั้งค่าภายในเครื่อง (Settings)

  • API URL ที่ผู้ใช้บันทึกไว้ใน chrome.storage ของเบราว์เซอร์ — เก็บในเครื่องผู้ใช้เท่านั้น ไม่มีการส่งออก

2.5 ข้อมูลทางเทคนิคของคำขอ (Technical / Server Logs)

  • เมื่อผู้ใช้ส่งเอกสารเพื่อสกัด เซิร์ฟเวอร์ประมวลผลอาจบันทึก metadata มาตรฐานของคำขอ เช่น เวลา, ที่อยู่ IP, ขนาดคำขอ ตามแนวปฏิบัติทั่วไปของผู้ให้บริการโฮสติ้ง (ดูข้อ 4.2) — ใช้เพื่อความปลอดภัย/เสถียรภาพเท่านั้น ไม่ใช้ระบุตัวบุคคล

3. วิธีที่ส่วนขยายใช้ข้อมูล (How We Use Data)

  • การสกัดข้อมูล: เอกสารที่ผู้ใช้เลือกถูกส่งผ่าน HTTPS ไปยังเซิร์ฟเวอร์ประมวลผลของส่วนขยาย (https://rsc-extraction-api.onrender.com) เพื่อแปลงเป็นข้อมูลโครงสร้าง (ชื่อโครงการ, ผู้ขอ, วันที่, วงเงิน, รายการค่าใช้จ่าย ฯลฯ)
  • การแสดงผล: ผลการสกัดถูกส่งกลับมาแสดงใน Review Card เพื่อให้ผู้ใช้ตรวจสอบ/แก้ไข
  • การกรอกแบบฟอร์ม: ข้อมูลที่สกัดได้ถูกกรอกลงแบบฟอร์มเว็บราชการ เฉพาะเมื่อผู้ใช้กดปุ่ม "ยิงข้อมูลลงแบบฟอร์ม" เท่านั้น — ไม่มีการส่งอัตโนมัติโดยไม่ได้รับความยินยอม
  • การตั้งค่า: API URL ใช้สำหรับเชื่อมต่อเซิร์ฟเวอร์เท่านั้น

4. การแชร์ข้อมูล และทุกฝ่ายที่ได้รับข้อมูล (Data Sharing & Every Recipient)

ข้อมูลผู้ใช้จะถูกส่งไปยังฝ่ายต่อไปนี้เท่านั้น ตามความจำเป็นในการทำงาน:

ฝ่ายที่ได้รับข้อมูล ข้อมูลที่ได้รับ วัตถุประสงค์
① เซิร์ฟเวอร์ประมวลผลของส่วนขยาย
(rsc-extraction-api.onrender.com)		 เอกสารที่ผู้ใช้เลือก + ข้อมูลที่สกัดได้ ประมวลผลการสกัด (ชั่วคราว — ไม่เก็บถาวร)
② Render.com — ผู้ให้บริการคลาวด์ที่โฮสต์เซิร์ฟเวอร์ Metadata ของคำขอ (เวลา/IP/ขนาด) ตาม standard server logs โครงสร้างพื้นฐานการโฮสต์/ความปลอดภัย
③ เว็บราชการปลายทาง
(rsc-approval.kmutt.ac.th)		 ข้อมูลที่สกัดได้ (เมื่อผู้ใช้กดยิง) กรอกแบบฟอร์มตามคำสั่งของผู้ใช้
④ เบราว์เซอร์/เครื่องของผู้ใช้ การตั้งค่า API URL (chrome.storage) เก็บในเครื่องเท่านั้น

การยืนยัน: นอกเหนือจาก 4 ฝ่ายข้างต้น ไม่มีบุคคล หน่วยงาน หรือบริษัทอื่นใดได้รับข้อมูลผู้ใช้ — ไม่มีการขายข้อมูล, ไม่มีการแชร์เชิงพาณิชย์, ไม่มี analytics/advertising SDK ของบุคคลที่สาม, และไม่มีการส่งข้อมูลไปยัง Google (นอกเหนือจากพฤติกรรมมาตรฐานของ Chrome Web Store)

5. การจัดการและการจัดเก็บข้อมูล (Handling & Storage)

  • ฝั่งเซิร์ฟเวอร์: ประมวลผลแบบ stateless — เอกสารและข้อมูลถูกใช้ในหน่วยความจำระหว่างประมวลผลแล้วทิ้งทันที; ไม่มีฐานข้อมูลถาวร ไม่มีการเก็บไฟล์
  • ฝั่งเครื่องผู้ใช้: chrome.storage เก็บเฉพาะการตั้งค่า API URL (ลบได้โดยล้างข้อมูลส่วนขยาย); ข้อมูลที่สกัดได้อยู่ในความจำของหน้า side panel ระหว่างใช้งานเท่านั้น
  • Server logs: จำกัดเฉพาะ metadata มาตรฐานของ hosting (ข้อ 2.5) และไม่ใช้ระบุตัวบุคคล

6. ข้อมูลที่ส่วนขยายไม่เก็บ (Data We Do NOT Collect)

  • ❌ ไม่เก็บ cookies / ไม่ติดตามพฤติกรรม / ไม่มี analytics
  • ❌ ไม่เก็บรหัสผ่าน / ข้อมูลการเข้าสู่ระบบ / authentication tokens ของผู้ใช้
  • ❌ ไม่เก็บประวัติการท่องเว็บ / ไม่เก็บตำแหน่ง (location)
  • ❌ ไม่เก็บข้อมูลติดต่อ (address book) / ไม่อ่านอีเมล / ไม่มีโฆษณา
  • ❌ ไม่เก็บข้อมูลของเด็ก (ข้อมูลที่ไม่ได้มาจากเอกสารที่ผู้ใช้เลือกเอง)

7. ความปลอดภัย (Security)

  • การรับ-ส่งข้อมูลทั้งหมดผ่าน HTTPS (TLS)
  • ส่วนขยายไม่มี remote code — ไม่มีการโหลด/รันโค้ดจากภายนอก
  • ขอสิทธิ์ (permissions) เฉพาะที่จำเป็นต่อการทำงานเท่านั้น

8. สิทธิ์ของผู้ใช้ (User Rights & Choices)

  • ผู้ใช้สามารถถอนสิทธิ์/ลบส่วนขยายได้ทุกเมื่อผ่านการตั้งค่า Chrome
  • การสกัดและการยิงข้อมูลเป็นการกระทำของผู้ใช้เองทุกครั้ง — ไม่มีกระบวนการอัตโนมัติที่ทำงานโดยไม่ได้รับความยินยอม
  • ผู้ใช้สามารถล้างข้อมูลการตั้งค่าที่เก็บในเครื่องได้โดยล้างข้อมูลของส่วนขยาย

English Summary (Complete)

RSC Doc → Smart Data is a Chrome extension by the RSC office, King Mongkut's University of Technology Thonburi (KMUTT), that extracts data from government documents (.docx/.pdf/.xlsx) chosen by the user and auto-fills the government portal form at https://rsc-approval.kmutt.ac.th/.

Data Collected

  • Files & Docs: the full content of document files the user selects, plus filenames/sizes.
  • Personal Information: data extracted from those documents (names, positions, departments, phone numbers, dates).
  • Financial Information: amounts/budgets/expense items contained in the selected documents.
  • Settings: API URL stored only in the user's browser chrome.storage (never transmitted).
  • Technical data: standard server request metadata (time/IP/size) as hosting infrastructure logs.

How Data Is Used

Documents are sent over HTTPS to the extension's processing server (https://rsc-extraction-api.onrender.com) for extraction. Results are shown to the user for review, and are submitted to the government portal only when the user clicks the fill button.

Every Party That Receives User Data

  • ① The extension's processing server (rsc-extraction-api.onrender.com) — receives documents for transient extraction.
  • ② Render.com — the cloud provider hosting the server; sees standard request metadata only.
  • ③ The government portal (rsc-approval.kmutt.ac.th) — receives extracted data when the user clicks fill.
  • ④ The user's own browser/device — stores the API URL setting locally.

No other party receives user data. No sale, no commercial sharing, no third-party analytics/ad SDKs, no data sent to Google beyond standard Chrome Web Store behavior.

Storage & Retention

Server processing is stateless — documents are used in memory and discarded; there is no persistent database or file storage. Local settings are limited to chrome.storage. Server logs contain standard hosting metadata only and are not used to identify individuals.

Data NOT Collected

No cookies, no tracking, no analytics, no passwords/authentication tokens, no web history, no location, no contacts/email, no advertising, no children's data.

Security / Rights / Contact

All communication over HTTPS; no remote code; minimal permissions. Users may uninstall at any time; all actions are user-initiated. Contact: RSC office, KMUTT.
